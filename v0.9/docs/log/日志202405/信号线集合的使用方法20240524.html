信号线集合的使用方法20240524

信号线模式

信号线有两种模式，一种是内置程序纹理模式，另外一种是图片纹理模式。

内置程序纹理模式

图片纹理模式

而一旦指定了 图片路径 ，就是进入图片纹理模式。

图片纹理的显示样式，和图片的内容有关。例如上图中使用的是这个纹理的显示效果如下

图片在这里：

这里的图片路径还可以是图像的base64码，如果点击 设置纯色渐变的执行按钮时，就会是这样的效果。这个按钮的作用是将图片路径填充为一个base64码图片。

这个图片只有一个像素高，不太好观察。这里简单描述以下，相当于一个两边是透明，中间有一点白色的图像。

属性介绍

  • 起始时间和传输时间一般不做设置。
  • 颜色用来修改亮点的颜色。
  • 背景颜色用来修改整个线条的颜色。如果是图片纹理模式的话，那么背景颜色将不起作用。
  • 线宽是信号线的宽度，单位是像素。
  • 弧线类型，用来决定线条如何在地球上绘制。
  • 变亮是一个布尔属性，开启后，融合模式会不一样，整个线条会更加明亮。
  • 深度检测，用来确定信号线是否会被遮挡。
  • 图片路径，用来指定一个图片纹理，一旦设置，就意味着进入图片纹理模式。
  • 设置纯色渐变，主要是方便测试，用了一个base64为的白色渐变图片来填充图片路径。
  • 图像重复次数，可以是小数，用来决定图像在线条上要重复多少次，注意只对图片模式有效。
  • 图像重复长度，单位是米，这个属性只在设置了GeoJson路径以后才会生效，它会自动计算GeoJson中每一个线条的长度，然后除以这个图像重复长度，来设定每一个线条的图像重复次数。注意是每一个线条的图像重复次数都会设置。
  • 运动方向，决定信号线的运动方向。对于图片纹理模式，不支持双向运动。
  • 位置数组集合，内部用来填写信号线的位置数组。注意，因为是多条线段，所以是位置数组的数组。
  • 数据，是一个JSON的配置信息，一旦启用，位置数组集合的设置将会被忽略。
  • GeoJson路径，一旦设置，将会自动解析GeoJson数据并使用，会自动忽略数据、位置数组集合两个属性。说白了，就是位置数组集合、数据、GeoJson路径，三者是互斥的，都是用来指定线条形态的。其中优先级最高的是GeoJson路径，其次是数据，最后是位置数组集合。
  • 允许拾取，用来确定是否可以被拾取。
  • 渲染回调，用来在渲染过程中，决定每个曲线的进度和颜色等等。

部分属性较为复杂，以下专门论述。

位置数组集合

通过设置位置数组结合，来创建信号线集合。

以上位置数组，需要自己一个一个的填数字，使用起来可能不太方便。实际使用时，可以通过创建多个信号线，然后再合并成一个信号线集合的方式来获得位置数组集合。使用方法如下图示，首先创建多个信号线，然后选中所有的信号线节点，然后打开右键菜单，选择合并为信号线集合。

注意，以上菜单中可见有两个合并为信号线集合的命令，第一个会保留原先的单个信号线，第二个会在创建的同时删除原先的信号线。一般用第二种。

数据

数据是设置线条的另外一种方式，一旦设置，那么位置数组集合属性将不起作用。 数据规格内部有两种模式，一种是常规模式，另外一种飞线模式。常规模式就是咱们刚才举的例子，而飞线模式只有两个点来组成的抛物线构成。

数据规格说明

数据规格如下。

export type STCRoutPathBaseType = {
    startTime?: number;
    transmissionTime?: number;
    repeat?: number;
    color?: [number, number, number, number];
    bgColor?: [number, number, number, number];
    bidirectional?: 0 | 1 | 2 | 3;
    extra?: any;
}

export type STCRoutePathType = ({
    // [k: string]: any;
    positions: ([number, number] | [number, number, number])[];
    width: number;
} | {
    // [k: string]: any;
    startPos: [number, number, number];
    endPos: [number, number, number];
    heightRatio: number;
    width: number;
}) & STCRoutPathBaseType;

其中STCRoutPathBaseType 作为基础类型，可以看到除了color、bgColor以外，还可以设置repeat、bidirectional等属性，extra则可以用来挂接其他额外属性，然后在渲染回调中可以获取。 STCRoutePathType 的内部有positions和startPos/endPos两种形式，分别对应常规模式和飞线模式。

GeoJson路径

该属性一旦设置，将会自动解析GeoJson数据并使用，会自动忽略数据、位置数组集合两个属性。 说白了，就是位置数组集合、数据、GeoJson路径，三者是互斥的，都是用来指定线条形态的。其中优先级最高的是GeoJson路径，其次是数据，最后是位置数组集合。

测试用的geojson数据如下： http://114.242.26.126:7000/data/my3dtiles-scene/北京公交流线/bj_bus2.geojson

渲染回调

用来在渲染过程中，决定每个曲线的进度和颜色等等。效果如下。

以下是该属性的示例代码：

// result 最后的结果
// sceneObject 是当前的信号传输器集合
// instanceIndex 当前的信号传输器集合的实例索引
// frameState 当前的帧状态
// 返回值如果是undefined，则相当于此函数不起作用。
function (result, sceneObject, instanceIndex, frameState) {
    const r = instanceIndex / 50;
    const c = r - Math.floor(r);
    result.color = [c*.5+.5, (1.0 - c)*.5+.5, 0.5, 1];
    result.bgColor = [c*.5+.5, (1.0 - c)*.5+.5, 0.5, 0.3];
    return result;
}

渲染回调的规格是这样的：

export type CzmSignalTransmissionCollectionRoutePathCallbackType = (result: XbsjPositionCallbackResultType, sceneObject: CzmSignalTransmissionCollection, instanceIndex: number, frameState: Cesium.FrameState | undefined) => XbsjPositionCallbackResultType | undefined;

渲染回调涉及的函数类型信息如下，这里使用的是typescript的写法。CzmSignalTransmissionCollectionRoutePathCallbackType 表示回调函数的类型信息，它有result, sceneObject, instanceIndex, frameState四个参数。sceneObject表示当前的场景对象自身，instanceIndex表示绘制的是第几个线条，frameState是当前Cesium的帧渲染状态，一般用不上。 result和返回值的类型都是XbsjPositionCallbackResultType。 XbsjPositionCallbackResultType的规格是这样的。

export type XbsjPositionCallbackResultType = {
    timeRatio: number;
    repeat: number;
    color: [number, number, number, number];
    bgColor: [number, number, number, number];
    bidirectional: 0|1|2|3; // 0/1表示单向，2表示双向, 3表示无信号
};

XbsjPositionCallbackResultType的规格说明：

  1. timeRatio是运动的位置，在0-1之间
  2. repeat表示最终的纹理重复次数
  3. color 表示亮点的颜色
  4. bgColor表示整个线条的基础色
  5. bidrectional表示线条运动的方向，0表示正向，1表示反向，2表示双向，3表示不运动

以上属性都可以做相应修改。
